## Ranked findings

None of these blocks the verdict. They are in order of weight.

1. **C22 waits on the owner** (see the top). The check now agrees with its proof, door 8 and AD-040(d). It narrows the
   approved AC 22 and door 7 for the run credential only. With the owner token nothing changes (C15).
2. **C22's test title still says the opposite of what it asserts.** `tests/contexts.runs.test.ts:297` reads "…the whole
   index with all; without a context, the whole index". The comment at `:370` says "A run without a context: the whole
   index, as before". Yet `:376-378` asserts `not.toContain(outsideNote)` for `all` and for the plain run. The
   `-t "C22 "` filter still selects the right test. The name misleads the next reader, and the next fixer if the owner
   picks the alternative.
3. **The typed-path form: keyboard and screen reader work, but a refused path gets no feedback.** I probed it in
   Chromium (a scratch spec, since deleted):
   - Tab goes Name → "Add folder" → "or type a path" → Cancel.
   - Enter adds an absolute path and clears the field. Focus stays in the field.
   - Enter in "Name" still submits the dialog. Enter in the typed path never creates the context, even while "Create"
     is enabled.
   - The hidden form's `<button type="submit">` is not in the accessibility tree. The dialog's buttons are "Close",
     "Remove …", "Add folder", "Cancel", "Index and create".
   - axe with every impact level (wcag2a/aa, 21a/aa) found no violations on the dialog with a path added.

   What is lost: a relative path plus Enter is silently ignored (`NewContextDialog.tsx:93` returns), with no message and
   no `aria-invalid`. Before the fix, the disabled "Add" button showed this. Nothing tells a screen-reader user that
   Enter adds the path. design.md draws only the field, so this is a question for the design, not a check gap.

4. **WebKit, the macOS shell's engine, was not run.** Playwright's WebKit downloaded, but the host lacks its system
   libraries (`libgtk-4`, `libgraphene`, …). The design relies on implicit submission through a hidden form's default
   button. The HTML standard requires that, and WebKit's `submitImplicitly` dispatches a click at the first successful
   submit button without a render check. That is reasoning, not a run. The config's own opt-in (`MORDOMO_E2E_WEBKIT=1`)
   is how to settle it on a Mac.
5. **The browser C32 failed once, then passed six times.** In the first batched run, `contexts.spec.ts:199`
   (`getByRole("combobox").fill`) failed with "Element is not an <input>". The palette had not opened after
   `Control+k`. It then passed 3 of 3 runs alone and 2 of 2 in the batch. The fix touched neither the palette nor this
   test. It is a timing flake, the same kind as round 1's `nucleo-shell` note.
6. **Validation in `newContext` that sits outside the decision table row 1 names** is proven only at the boundary: the
   50-context cap, a malformed or taken given `id`, the `-2`…`-99` derivation, and two paths with one real folder
   (`contexts.ts:301-316,266-279`). C2 and C4 prove these at the boundary. The duplicate check uses the same platform
   folding as door 6, so on macOS `/A` and `/a` are one folder, and no test asserts that. No check claims it.
