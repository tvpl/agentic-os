### Achados bloqueantes (ranqueados)

1. **Diff por git lê arquivo bloqueado pelo filtro, por magia de pathspec** - CONFIRMED por execução. `apps/api/src/routes/runs.ts:460` passa `rel = path.relative(repoRoot, resolved)` como pathspec (`:463`, `:464`, `:467`) e `apps/api/src/routes/git.ts:30-35` não define `GIT_LITERAL_PATHSPECS=1`. O filtro vê o nome `*`, `:(top).env`, `?env` ou `[.]env`, que não casa com `.env*`; o git expande o pathspec e devolve o diff dos arquivos rastreados e alterados. Num repositório da pasta indexada com `.env` e `server.pem` rastreados e alterados, `GET /api/runs/<id>/diff?file=<repo>/*` devolveu `API_KEY=HUNTER2-CHANGED` para o dispositivo e para o dono (`<repo>/.env` literal: `unavailable`; `*.pem` literal: `unavailable`; `:(glob)**/.env`: `unavailable`). Derrota o AC 18 e a frase do T12 "the path goes through the workspace filter before git starts". Correção: `GIT_LITERAL_PATHSPECS=1` no ambiente (ou `--literal-pathspecs`) e uma prova com glob.
2. **O diff por git alcança `config/token` por `core.worktree`** - CONFIRMED por execução (git real, pela rota). Um `.git/config` com `core.worktree = <home>/config`, e um commit que rastreia um arquivo `token`, faz `git diff HEAD -- token` comparar com `<home>/config/token`: a rota devolveu o token do dono ao dispositivo e ao dono (`file=<repo>/token`, que o filtro vê como arquivo comum). Pré-condição: quem planta o repositório precisa de git (ou de um repositório pronto, de um tarball): é a mesma capacidade de "agente com shell", mas o T12 trata o config do repositório como hostil e `core.worktree` não está neutralizado (`git.ts:19-28`), e o ativo é o token do dono. Correção: `--git-dir`/`--work-tree` explícitos em `runGit`. A rota aceita `file` de qualquer pasta concedida com qualquer id de execução (`runs.ts:150-158`), então o dispositivo escolhe o arquivo.
3. **A documentação subestima o resíduo** - por leitura. `docs/security.md:113` diz que "a paired device that can start a **write** run can therefore reach the token". `POST /api/runs` usa o home como `cwd` quando o corpo não traz um (`apps/api/src/routes/common.ts:276`), e uma execução `read_only` do Claude roda em `--permission-mode default` (`adapters/claude/src/index.ts:226-237`) cujo `Read` dentro do `cwd` não pede permissão; no Codex o modo `read-only` lê o disco todo. Logo basta uma execução de leitura com o `cwd` padrão. Não executei por falta dos binários. É um erro de uma palavra que muda a decisão de quem pareia um celular.
4. **Mutantes sobreviventes** (ver Faults): M26 (`core/src/engine.ts:230`, AC 17 sem prova), M12 (`core/src/security/safeFs.ts:344`, link dentro do que se importa), M32 (`core/src/memory/journal.ts:113`, append por link pendente que C20 afirma), M29 (`core/src/memory/search.ts:66`), M50 e M51 (`tests/fsReadAudit.ts:30,46`, C31), M20 (`scheduler.ts:670`), M24, M36, M38 (`compiler.ts:283`).
