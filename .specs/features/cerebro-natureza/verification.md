## Judgments asked for

1. **C2 "errors: 0" is faithful.** `IndexStats` (`contracts/src/events.ts:63-76`) has no `errors` key, and the only failure signal of a pass is `index.failed`. The proof asserts `events.map(e => e.type)` `toEqual(["index.finished"])` (`tests/natureza.index.test.ts:98`). It then asserts that each of the files is a hit with both its read value and its stored value (`:103-106`). That is stronger than a count, because a file whose read had failed would have no hit with its `fields`. There are two imprecisions in the check, neither of them a gap. The claim says "these five files" but lists seven cases. And `stats.added >= 7` (`:99`) is a lower bound, which the per-file hits compensate for.
2. **C52 without the inode is supported by AC 32.** AC 32 says the note "SHALL NOT delete or move the file". Door 4 routes the decision through `saveProperties`, which writes a temporary file and renames it over the note, so the inode always changes. The reworded proof asserts that the path is the same, that the listing of every name under the home is unchanged (`tests/natureza.decisions.test.ts:353`), and that the file is still a file (`:354`), which is what "not delete or move" means. There is one bookkeeping drift, which is not a gap. Amendment 24 sits after `## Sources` (`plan.md:458-461`) and names "Pergunta cerebro-natureza 10", but the questions table stops at 9 (`plan.md:436-444`). The header of checks.md still says "23 amendments" (`checks.md:9-10`).
3. **The `--tone-*` badge classes are faithful.** design.md asks for colours "do conjunto existente … sem cor nova", and the names it gives do not exist in `theme.css`. Holding the design to structure and the system to values, each class is coloured by an existing token: `natureza.css:14-28` maps `--ok`, `--info`, `--warn` and `--accent-text`. `tone-muted` has no rule of its own and inherits `--text-dim` from `.badge.meta` (`theme.css:1421-1427`). The C74 stylesheet assertion (`natureBadges.test.tsx:115`) covers the four explicit tones; the muted one holds by inheritance. This is a precision note.
4. **"Não classificado" on every hit and preview without a nature is asked for.** design.md "Busca e preview" says "Cada resultado da busca … ganha o selo de natureza", and its table gives "(nenhuma) → Não classificado / `CircleDashed`". The preview shows "os selos de natureza e de escopo". The plan's assumption is "Nota sem natureza: 'não classificada', nunca presumida fato". There is one asymmetry, which is not a contradiction. A non-Markdown hit (for example a PDF) also reads "Não classificado", while the preview of the same file shows no badge (`PreviewPanel.tsx`, gated by `isMarkdown`; C87 asserts that a `.pdf` has none).
5. **`v` for "Ainda vale" does not collide at HEAD, but the guard is unproven.** I swept the registry. Its bare-letter keys are `?` global; `/`, `r`, `c` in `view:runs`; `/`, `p`, `n`, `f`, `l` in `view:brain` (`SecondBrain.tsx:599-619`); digits, `[`, `]`, `/`, `p` in `nucleo`; `v` in "Ver notas"/"Ver grafo" (`view:brain`, `BrainViewSwitch.tsx:70,84`); and `j`, `k`, `v`, `a` in `view:reviews` (`ReviewsScreen.tsx:324-349`). The only overlap is `v`. The builder dropped it from "Ver grafo" while the mode is `reviews` (`BrainViewSwitch.tsx:84`). Without that drop, `v` falls through to "Ver grafo" whenever "Ainda vale" has no `when` (the "Sem classificação" tab, or an empty list), which the probe confirmed. No proof covers the drop: fault F8 survived. The help sheet titles the block "Revisões" (`ShortcutsHelp.tsx`), and no binding shortcut of `comandos-atalhos` is contradicted.
