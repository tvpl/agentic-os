Summary: the product defects of round 1 are fixed and hold on screen. Canvas text now measures at least 12px on a recording canvas that multiplies the camera scale, sprite scale and density (zoom 0.3, 1, 9; hover, selection, area chosen; Núcleo scene; HUD at three densities; Replay), the `.dimmed` legend state passes axe in both themes (the same state fails on the base, both themes), the hierarchy and halo read well in screenshots, no layout overflow appeared on 52 screens x base/head, and no e2e failure is new against cd2bf28. The verdict is still FAIL because the new guards, the thing this round was asked to attack, have holes that the probes found and that no proof catches: a canvas font written in `pt`/`rem`/`em` or a keyword is invisible to both C3 and C17 even when drawn on every frame; a text drawn in a state the C17 tests never reach survives; the structural guard misses five spellings of `fillText`; three config-file forms switch the colour lint off while C5/C6 stay green and `npm run lint:css` exits 0 with `#fff` in the tree; C15 exempts whole class names and only reads `<p>`; C16's vocabulary leaves `aria-expanded` and others out. None of these holes is exploited in today's tree (grep and the screens agree), so this is guard strength, not a regression; each is a small fix.

## Ranked findings

1. **AC 3 guard hole: canvas font units other than `px` are invisible to C3 and to the recording canvas** (C3, C17; surviving mutants M6a, M6b). `ctx.font = "8pt monospace"` or `"0.5rem monospace"` plus a `fillText`, drawn on every frame inside `drawFrame`, passes `typography.test.ts` and all four `canvasText` tests: `CANVAS_FONT` in `testing/sizeScan.ts:512` only matches `px`, and `fontPx` in `testing/canvasText.ts:49` returns null for any other unit and `draw` (`:76`) silently records nothing. design.md "Piso" says no canvas text under 12px. Fix: make `fontPx` throw on a font it cannot read, and teach `CANVAS_FONT` `pt|em|rem|%` and size keywords.
2. **C5/C6: the colour lint can be turned off by a config file the guard does not know** (surviving mutants N1-N3). With `#fff` in `views/apps.css`: a nested `apps/command-centre/src/.stylelintrc.json` (`color-no-hex: null`), a root `.stylelintrc.yml` extending the config, or a root `stylelint.config.cjs` each leave `C6 the tree passes the colour lint` green (`typography.test.ts:482` runs `npx stylelint` with discovery on, so it reads the same file) and `npm run lint:css` exits 0. The guard lists five root file names (`typography.test.ts:522-527`) and the `package.json` key; stylelint's discovery also reads `.stylelintrc.yml/.yaml/.cjs/.mjs/.ts`, `stylelint.config.cjs/ts` and any config in a directory above a linted file. AC 5/6, Landing door 2. Fix: pass `--config` explicitly in `lint:css` and in the C6 run, and forbid any other config file in the tree.
3. **C17's structural guard is file-level and syntactic** (M5b, and five spellings). (a) A `fillText` added in a listed file under a state the measurement tests never reach survives: `draw.ts` text drawn only when a search matches (`w.matched !== null`, absent from `states()` in `brain/render/canvasText.test.ts:80-105`), at a size C3 cannot see (a function parameter named `k` called with `k * 2`, 6px on screen), passes everything; the same text drawn on every frame is killed (M5c). (b) `ctx.fillText.bind(ctx)`, `const { fillText } = ctx`, `ctx['fillText'](…)`, `Reflect.apply(ctx.fillText, …)` and `CanvasRenderingContext2D.prototype.fillText.call(…)` in a new file are not call sites for `canvasTextSites` (`typography.test.ts:270`): the C17 structural test stays green (a direct call, a `strokeText`, an `(ctx as any).fillText`, a `c.fillText` through a parameter and `ctx?.fillText?.()` are found). The search-match state is also a state that adds text (ranking boost of matched labels), which the C17 claim ("em cada estado que acrescenta texto") covers.
4. **C15: exemptions by class name are global, and the rule reads only `<p>`** (surviving mutants P1-P4, P6-P8). `MICROCOPY` (`typography.test.ts:185`) exempts a class wherever it appears: `.page-head .sub { font-size: var(--fs-2) }`, `.provider-gate-head .sub`, `.cx-audit .meta` and `.cons-interim.mono` at 12px all pass, although `.sub` carries a skill description (`views/Skills/SkillDetail.tsx:189`), the provider-gate body (`components/ProviderGate.tsx:80`) and subtitles; `.meta` carries sentences on a `<p>` (`views/Connectors.tsx:104,119`, `views/settings/providers.tsx:108`) and `.mono` a live transcript line (`desktop/console/Console.tsx:745`). The rule does not read a `<div>`/`<span>` description: in the browser scan, `<span class="cx-purpose">` connector descriptions (59-121 characters, `views/backend.css:308-312`, `--fs-2`) are 12px on the Connectors screen, which design.md calls "descrições". A class on a `<p>` through a wrapper component prop or a lookup object is not seen. Browser scan of 13 routes x 2 themes x 2 widths found no `<p>` of running text under 13px (every small `<p>` is a label, key hint, eyebrow or counter), so the 30-entry list holds for `<p>` today; the contest is on strength and on the `cx-purpose` description.
5. **C16 vocabulary and what counts as a mark** (surviving mutants S1-S7). The state words (`typography`/`stateScan.ts:18`) leave out `[aria-expanded]` (colour-only today: `.bs-more[aria-expanded="true"]` `nucleo/scenes/brainScene.css:669`, `.cons-ctl .ro[aria-expanded="true"]` `desktop/desktop.css:1657`), `.is-selected`, `[data-state]`, `[data-active]`, `[aria-current="location"]`, `.dot.ok/.warn/.danger` and `[data-status]`; a colour-only rule on any of them passes. Any property outside the colour list is a mark: `box-shadow: 0 0 8px red` (a glow), `pointer-events`, `z-index` and a gradient `background-image` pass `.t.on { color: red; … }`. A `::before/::after` of any kind marks the group. `MARKED_ELSEWHERE` has 11 entries, not 10; I accept `.tabs [role="tab"][aria-selected="true"]` (verified: `border-bottom: 2px solid transparent` at `theme.css:1692`, colour set at `:1712`) and `.palette-row.selected` (the row is also `.launcher-result`, `CommandPalette.tsx:825`, filled by `theme.css:998-1001`); `.rts-lane.off` is weak (the dial lane of a paused routine differs by colour only; the list row says it in words) and `.rts-item.on` rests on `aria-expanded`, which a sighted reader does not see, though the detail panel opening is a visible mark.
6. **C3 arithmetic and spelling blind spots** (surviving probes, none in the tree). `Math.max(14, w) - Math.max(2, h)` is bounded at 12 (subtraction of a lower bound: unsound); `x / k` is trusted for any identifier named `k` (a `const k = 0.5` or a parameter called with a sprite scale: the convention is documented in the check but not enforced); `"700 " + 8 + "px" + " mono"`, `['700','8px','mono'].join(' ')`, `"8px/1 mono"` as a font, `setAttribute('font-size','8')`, `{ ['fontSize']: 8 }` and `el.style['fontSize'] = '8px'` are not seen. C17 kills the `+` spelling when it is drawn on every frame (M6c), the others only with item 1's fix.
7. **C5 colour lint: system colours and `data:` only through listed properties.** `Highlight`/`Canvas` in `box-shadow`, `text-shadow`, `filter: drop-shadow()`, `-webkit-text-fill-color`, `stop-color` and in a custom property (`--c: Canvas`) are accepted (the value list in `stylelint.config.mjs:39-48` names a property set). Every other probe was refused (see Faults: `color()`, `device-cmyk()`, `data:` URI in 5 places, system colours in 7 properties, 19 colour functions and names, `light-dark`, `@supports`/`@layer`/nesting/`@property`), and the three inline/comment disable forms are caught by C6's offender scan.
8. **Process and documentation.** (a) C13 as rewritten (see its row): the proof was changed after approval, from the full suite to ten specs with a "passes alone on the head" escape, without a user stop-and-ask (critical rule 3); the evidence supports the claim, so I judge the new rule acceptable as a measurement but the edit itself should have been the user's call. checks.md C13 still names `dae68bd` as "o pai desta correção"; the parent is cd2bf28. (b) Landing door 2's literal shape lists four colour functions and one rule; the config has eleven functions and a value-disallow rule (a superset; Landing is additive, so a row should have been added). (c) Heaviest unit test, C3, takes 2.8 s alone and exceeded vitest's 5 s default (`Test timed out in 5000ms`) when run in parallel with the other five files under load; 1 of 3 full-suite runs also timed out an unrelated Núcleo test. Only C5/C6 carry a 60 s timeout.
9. **Observations, not findings.** Light theme: yellow `ROUTINES` and light-blue `APPLICATIONS` ring names have low contrast on the page (they sit on a page-colour band; data palette, out of scope per the plan; base is the same colours). At zoom 0.3 the ring names and `ROUTER.MD` crowd the small map, none overlaps another (placer works). At 900% the core label sits over the pixel-core glyph; the halo keeps it legible. A transient "other service process(es) are running" banner appears in one head screenshot from leftover processes of my concurrent runs, not from the code. Code quality: the redundant `Math.max(12, …)` of round 1 was removed (`brainPaint.ts:1492,1608`), `initials` moved to `labels.ts`, the `hex()` sprite lost its `label` argument; `drawHaloText` leaves `lineJoin`/`lineWidth`/`strokeStyle` set but every later stroke in `drawFrame` sets its own (screens agree).
