# Design system verification

**Verdict**: FAIL
**Profile**: ui
**Diff range**: c2d5aef..8689b35 (8689b35^..8689b35; tip of the branch is now 730ff5d, whose later commits are security/core and do not touch this diff; every proof ran in a clean worktree at 8689b35, built with `npm ci`, `npm run build:server` and the command-centre build)
**Round**: 1 - full
**Verifier**: independent sub-agent (author != verifier)

Summary: all 14 proofs are green or no-worse-than-base, and every fault injected into the proofs was killed except the blind spots listed below. The verdict is FAIL because two things the feature promises are false on screen while the proofs stay green: canvas text below 12px survives (AC 3 / design.md "Piso"), and a reachable state of the Memory legend fails axe (design.md "Acessibilidade"). Two design.md rules have no check at all.

## Ranked findings

1. **AC 3 is not true on screen; C3 cannot see it** (precision gap in C3, plus the code). Measured by wrapping `fillText` and multiplying the parsed font size by the canvas transform scale (Memory brain, moldura, dark, 1440). Zoomed out (ZOOM_MIN 0.3, `brain/engine/world.ts:214`) text is drawn at 4.5-7.6px (planet counts, `brain/render/glyphs.ts:92`, `12 / Math.max(0.8, k)` is 12px only for k >= 0.8) and ring labels at 6.4-10.9px (`brain/render/draw.ts:445`, `15 / Math.max(0.7, k)`, unchanged by the feature). Independent of zoom, the hex sprite initials ("PL", "PS", "EM") are painted at 17.9px into a 96px sprite and drawn at 36px (`brain/render/sprites.ts:129`, `brain/render/draw.ts:370-376`), about 6.7px on screen (crop in the screenshots). `numberBound` in `typography.test.ts` reads `size / k` as the screen size, so a clamped divisor or a sprite scale passes. Mutant U48 (`8 / Math.max(0.8, k)`) is killed only because 8/0.8 < 12; the real expression 12/0.8 passes while drawing 4.5px.
2. **A reachable state fails axe**: `.brain2-legend .lg-row button.dimmed { opacity: .45 }` (`brain/brain.css:243`), set by `BrainChrome.tsx:218` when an area is chosen in the legend. With the class applied, axe (wcag2a/aa/21a/21aa) reports `color-contrast` serious in both themes (dark 2.56 and 1.99, light 2.06 and 1.90, 12px text). C8/C9 never enter that state, and the author fixed the sibling `.kind-off` (same .45 opacity) in this very diff. design.md: "O contraste de texto segue AA (4.5:1)". The e2e home has a single area, so I forced the class in the DOM; the state is reachable with two or more areas.
3. **Two binding rules with no check** (Uncovered): "Texto corrido (parágrafos, descrições, mensagens) usa no mínimo --fs-3 (13px)" and "um estado nunca é comunicado só pela cor". The first is visibly not followed: `<p class="brain-hint">` at `brain/brain.css:53-55` and `.field .hint` at `theme.css:1546-1547` are 12px paragraphs. The checks' exemption only names spacing and weight, so this is a blanket gap, not an enumerated one.
4. **Canvas label hierarchy is flattened and now collides** (composition, no check). Counts 8.5/9 -> 12, hub names 11.5 -> 12, planet names 9 -> 12, orb labels 10/10.5 -> 12, core label 11 -> 12: counts, hub names and the core label are all 12px/800, and the hub box height `13 / k` (`draw.ts:~410`) was left as is. In the 1440 dark and 800 light Memory screenshots the counts "13", "17", "7", "15" sit on the link arcs and "DOCS 116" on the purple arc (side-by-side base|head crop). The plan's assumption "o layout se ajusta" held for CSS HUDs, not for the canvas.
5. **C6's second half is only partly proven; colour-lint blind spots.** `color: #fff /* stylelint-disable-line */;` (comment inside the value) passes `npx stylelint` and the whole `typography.test.ts` (the comment lives in the declaration raws, not a comment node), so the claim "the only places with the rule off are the token blocks" is not enforced for that form. Config-level escapes (`ignoreFiles`, `overrides`) also pass (L5, L10 survive). `color(srgb ...)`, `device-cmyk()` and hex inside an SVG `url("data:...%23ff0000")` are not refused by the lint (K9, K12). None occurs in the tree today (the grep of `url(data:` in CSS is empty).
6. **C3 blind spots, none present in the tree today** (U40-U44 survive): JSX `fontSize={9}` / SVG attribute, `el.style.setProperty("font-size", ...)`, `style.cssText = "font-size:9px"`, shorthand `{ fontSize }`, and an HTML string with `style="font-size:9px"`. `min()` has no probe (T11 survives). C2 prose says rem/em use a 16px base; the code uses 12px for `em` and `%` (stricter, not a contradiction, but the check text is wrong).
7. **Code quality (low)**: `Math.max(12, groupPx(span))` and `Math.max(12, labelPx(...))` in `nucleo/scenes/brainPaint.ts:1492,1608` are redundant (both helpers already clamp to 12; `brainLabels.test.ts` kills the floor regression, U37) and exist to please the checker. Several stylelint "off on purpose" comments are partly untrue (see Stylelint below). Behaviour changes outside the plan's Surface: `.cons-h.dim` rule and class removed (`desktop/console/ConsoleTray.tsx:22`), `.inbox-row.read` opacity turned into a title colour, `.kind-off` opacity turned into a colour; the `luz.css` modal selectors gained `:not([data-shell="moldura"] *)` (+1 class of specificity on production rules, to serve the gallery). No new `!important` (the 6 added lines replace 6 existing ones). The 9 darwin gallery baselines are stale by the approved assumption.
8. **C13 evidence is weaker than the author's baseline suggests**: see the C13 row. The author's 27-failure baseline is mostly machine-load flakiness; no new failure in the feature.
