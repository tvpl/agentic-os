# Cérebro: memória confiável verification

**Verdict**: FAIL
**Profile**: ui
**Diff range**: a5b332e..a5d771f
**Round**: 1 - full
**Verifier**: independent sub-agent (author != verifier)

Every check C1-C159 was run at `a5d771f` and every one of the 190 `Proof:` lines resolves to tests that ran and passed
(root 2700 passed / 1 skipped, UI 1627 passed, e2e `memoria.spec.ts` 9 passed, `bundle:check` exit 0). The verdict is FAIL

## Ranked findings

1. **The `MEMORY.md` guard can be bypassed (door 8, AC 72).** A write run that grows `memory/MEMORY.md` past 4 MiB, or
   replaces it by a symlink to a file it wrote, keeps its change: no put-back, no `memory_edit` proposal, only a
   `console.error`. `core/src/memory/memoryGuard.ts:58` (`maxBytes: 4 MiB, strict: true` throws `FileTooLargeError`),
   `:99` (`putBack` throws `PathAccessError: Refusing to write through a link`), `:126-128` (only `EditConflictError`
   and `EEXIST` are caught), `:150-155` (the rest is swallowed). Observed by probe G1/G2 (scratch worktree):
   `restored: false … proposals 0`; `link stays: true … proposals 0`. Coverage of "guard cases" leaves these unproven.
2. **A device reads the output of a run it is told does not exist (AC 91, amendment 5, G11).** With `notes/fin` hidden
   from devices, a run whose `cwd` is there is `404` to the device (C150 holds), but `GET /api/artifacts/recent` and
   `GET /api/artifacts/list` name that run id and `GET /api/artifacts/file` answers `200` with its artifact text.
   `apps/api/src/routes/runs.ts:238-273` and `apps/api/src/routes/system.ts:306-316` iterate every run without
   `hiddenRun`; `runs.ts:241`/`:282` scope only denies `artifacts/exports/`. Probe D1.
3. **G14 is bypassed through the raw artifact.** A consolidation's `artifacts/<runId>/proposal.json` whose op is sourced in
   `notes/fin/segredo.md` and quotes it is served whole to a device by `GET /api/artifacts/file` (`200`, the hidden text
   and the relative path), while `GET /api/memory/proposals*` hides the stored proposal (C116). Probe D2.
4. **C113 and C120 are false as written (amendment 4 hides the score, not the order).** bm25's IDF is computed over the
   whole index, hidden rows included. Probe O1/O2: visible `a.md`/`b.md`, 40 hidden notes with `zebra`: the device and a
   write run's credential get `[a.md, b.md, …]`, their twins `[b.md, a.md, …]`. `apps/api/src/access.ts:145`
   (`rankScored` replaces only `score`), `apps/api/src/routes/memory.ts:210`. The proofs pass on their one fixture
   (`tests/memoria.access.test.ts:322`, `tests/memoria.access-runs.test.ts:178`).
5. **Free-text redaction misses common spellings (amendment 5).** `PATH_IN_TEXT` (`apps/api/src/access.ts:156`) stops at
   whitespace and needs a leading `/` not after `~`: a hidden folder `notes/Fin Pessoal` cited in a visible run's
   prompt reaches the device as written (probe D3: `promptSummary: compare …/notes/Fin Pessoal/segredo.md com o
resto`); relative (`notes/fin/segredo.md`) and `~/` citations are never judged (probe D5). C150-C158 prove only
   absolute paths without spaces.
6. **An agent can write a `MEMORY.md` line without the authorship mark (door 7, AC 58).** `OpText` is
   `z.string().min(1).max(500)` (`contracts/src/api/memory.ts:437`), newlines allowed, and the applier interpolates it
   unsanitised (`core/src/memory/proposals.ts:457`). Probe I1: an accepted `add` op with text
   `"Turmas de 15\n- Decidido pelo dono: …"` wrote `- Turmas de 15` with no `fonte::`, `autor::` or `em::`. Precision gap
   on C54 (no check states the one-line invariant).
7. **Surviving mutant F11.** `core/src/memory/folderAccess.ts:116` (`agents: "read"` of the resolver's own fail-closed
   entry) set to `"write"`: C112 stays green. The stored schema accepts a relative path (`contracts/src/settings.ts:73`),
   so a hand-edited list reaches `folderAccess.ts:96-98`; no proof does. The guard's "run deleted `MEMORY.md`" branch
   (`memoryGuard.ts:121-125`, A2 settled (d)) has no proof either.
8. **`Test policy` row 1 not met.** It names "the op applier" and "the proposal.json schema" among the deciders that need a
   proof at their own layer with one case per row; `tests/memoria.layer.test.ts` has no describe for either (its
   describes: C1, C8-C11, C17, C20, C25, C28, C51, C52, C59, C110, C111, C126). The 11 schema refusals are proven only
   through the hook (C49) and the op kinds only through `decide` (C54-C58).
9. **Step 1: elements design.md decides that no check covers** (see `## Binding sources`): the two regions of "Do
   agente" (list left, detail right), the diff's two line-number columns, the tone of the `ferramenta`/`inferido` badges
   and of the diff rows, the 12px of the permissions modal's hints and "Herdado de" (built 13px), the list state in
   `role="status"`, and the restored note's "Salvo" state and conflict band (cerebro-v2).
10. **Residual risks, judged and not FAILing on their own:** `x-total-count` (B1b's documented limit, acceptable: counts
    only); the `mordomo mcp` tools read with the owner token, so an agent session that has them reads hidden folders
    (written for writes in `docs/security.md`, not in its folder-access "Limits"); the triage sentinel puts sentinel
    bodies verbatim into a model prompt (`core/src/sentinels/triage.ts:83-86`; `fsWatch` names the watched folder);
    `knownAt` returns a closed fact with the `valid_to` set after K (closing is in place); the byte cap can evict an owner
    version of `MEMORY.md` recorded during a long run, after which the guard would revert it (theoretical).

## Judgments asked for

- **B1b's reading of C113.** Comparing with the owner twin whose scores are mapped to `1 / position` is the only reading
  under which amendment 4 ("C113 e C120 seguem como escritos, por valor") and the claim can both stand, and it is fair
  for the score. It does not make the claim true: the order of the hits is still bm25 over the whole index, and probe
  O1/O2 shows a device and a run receiving a different order than their twins. C113 and C120 FAIL; the fix is an order
  computed without hidden rows (or a claim that names the order as a written limit, an owner question).
- **B2's 13px hints.** `design-system/design.md` (binding, and named by this feature's own design.md) puts prose at
  13px or more and keeps 12px for labels, counters and metadata. The six hints are sentences, so 13px is right and the
  feature's "12px" is its own inconsistency; `folderTools.css:2-3` says so. "Herdado de <pasta>" is a short label, for
  which 12px satisfies both sources, and it was built at 13px. No check fixes either size (U4).
- **G6 (`proposals.ts`, `safeWrite.ts`).** Sound: a created file is removed only when its path re-resolves to the same
  real path inside the scope and `lstat` shows a regular file with the same device and inode
  (`safeWrite.ts:118-125`, `:408-417`); replaced files get their bytes back guarded by the bytes written; F22 is killed
  by both C63 cases. Residual: a window between `lstat` and `unlinkSync` in which a parent swapped for a link would let
  the unlink act elsewhere (needs a race at the owner's own decision; low), and inode reuse (low).
- **Bi-temporal facts and G24.** `overlapAction` (`facts.ts:183-194`) is door 2's table row for row, with the
  boundaries at T and U proven and F2 killed. G24's refusal is conservative and matches door 2's rejected alternative
  (no row nobody stated). Limitation worth an owner note: closing writes `valid_to` in place, so `knownAt=K` returns a
  fact with the `valid_to` recorded after K; transaction time covers creation and retraction only (AC 12 defines it so).
- **Retention at both edges.** Count: the 50th kept, the 51st drops the oldest by id (`historyStore.ts:111-114`; C27,
  F3). Bytes: exactly at the cap drops nothing, the newest 5 of a path are never dropped, unnamed blobs are deleted
  (`:126-145`; C28, F4); G3 holds. The floor counts `guard` and `removed` versions too: two `guard` versions per guarded
  run can push the owner's versions of `MEMORY.md` out of the newest 5, and above the cap an owner version recorded
  during a long run could be evicted before `run.finished` (the guard would then revert it); theoretical, unproven.
- **`x-total-count`.** Acceptable as B1b's written limit: it leaks counts (and counts per `status`/`skill` filter), never
  paths or content, and `docs/security.md` says so.
- **The proposals inbox.** Decide is owner-only (C68), guarded by `baseVersion` (C62), the topic slug is restricted
