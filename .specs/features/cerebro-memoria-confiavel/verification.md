1. **The `MEMORY.md` guard is still switched off by the run it guards (door 8, AC 72, amendment 8; round 1 finding 1 only
   half closed).** The take-back of an entry the plain put-back cannot handle (a link at the name, a file past the 4 MiB read)
   needs `memory/archive/` to be a folder the guard can write to, and a write run owns that folder. A run that makes
   `memory/archive` a regular file (or a link), then grows `MEMORY.md` past 4 MiB (or replaces it by a link to a file it
   wrote), keeps its change: observed `MEMORY.md` of 5 242 891 bytes starting `- INJECTED` after `run.finished`, and a link to
   the run's payload, the proposal stored, and one inbox row of tone `danger` saying `the guard could not put MEMORY.md
back: EEXIST: file already exists, mkdir '…/memory/archive'`. The agent's text is what the next session loads (the first 25 KB).
   `core/src/memory/memoryGuard.ts:189-197` (`takeBack` → `setAsideAndWrite`), `:225` (`forced()` is the only path for an odd
   entry), `:222` (the failure is collected, nothing else is tried), `:281` (`restored ? "warn" : "danger"`),
   `core/src/security/safeWrite.ts:498-515` (refuses a link on the way to `to`, `fs.mkdirSync` throws on a file). The fix of
   round 1 closes the cases the tests build (a clean `memory/`), not a `memory/` the run has prepared. Probes G-B, G-C. C69 FAIL.

   read); a link inside `memory/` was not. Probe G-A. Needs the run to create a link (Claude's `Bash` asks a human; Codex and
   Cursor do not, outside a hidden-folder run folder); no check names it.

## Judgments asked for

- **The guard's inbox row (the brief's "what it quotes").** `tell()` (`memoryGuard.ts:130-148`) writes the run id, one of four fixed
  reasons, the aside name `archive/guard-<runId>-MEMORY.md` and the message of the step that failed (observed: system paths,
  `EEXIST`, `Refusing to move through a link`). Nothing the agent chose is quoted, so the row is not a channel for text into
  `inbox_unread`. The row is shown to a device unless the run is hidden from it; it holds no hidden path.
- **`memory/archive/guard-*` and a device.** A regular aside holds the run's bytes under a path a device may read (any
  `memory/archive` file is a note like another and is indexed); an aside that is a link is not followed (probe G-A: `404`). So a
  device reads what an injected run wrote, as it reads the proposal; that is not a hidden folder. It also lets the run's text
  be found by search and recall for later agents; the plan's assumption says the other notes of `memory/` are not guarded.
- **Concurrent passes against the audience tables.** The mirror is built inside the write transaction (`indexer.ts:327-335`
  resets it after each) from the `meta` row, `ensureAudienceIndex` empties, refills and writes the row in one transaction, so a
  crash leaves either the old table and row or the new, never a mix; a pass that starts with older settings than the
  main thread can rewrite the row to the older spec, and the next read of that audience rebuilds it (`ensureAudienceIndex` runs
  before every search and recall). The window between that read and its query is the only one; the route's own row filter still
  applies, so it can only change an order, not show a file. Observed in probe AUD1.
- **Exports.** The export copies whatever the owner reads, hidden subfolders included, to `artifacts/exports/`; no device route
  serves that folder (C116, F15's branch is the index's side of the same rule), and a run credential has no route to it. A
  copy under an indexed root would reach agents' search; nothing proves the rule for devices there (F15).
- **The history store and a hidden path.** Versions of a hidden path are `[]` for a device and a hidden id is `404` with the
  body of a missing one (probe H1), so there is no oracle by status. The leak is the move (finding 6).
- **MCP tools.** `facts_assert`, `note_create`, `note_save` propose (`apps/api/src/mcp/mordomo.ts:134-232`), `journal_append`
  sends `author: "agent"`; the owner's token reads hidden folders through `recall`, `note_read`, `facts_query` (documented in
  `docs/security.md`). A forged `trust` or `author` in a proposal body is dropped (F-A).
- **G36, G35, G37, G38** are owner questions with a safe default asserted by a check; none changes a verdict by itself.
