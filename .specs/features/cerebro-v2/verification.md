## Confirmed (attack list)

- **409 mapping and attacks.** Probe through the HTTP route with response validation on (`validateResponses: true`): an editor's rename over the note during our `fsync` is `409 edit_conflict` with the editor's text kept and no temp left; a `EBUSY` rename is saved in place (`200`, `path/name/version/size/mtime`, same inode, the version equals the SHA-256 of the bytes on disk); a symlink to `config/token` planted during the fallback is `403 forbidden_path` and the token is intact (65 bytes). Core primitive: symlink swapped in under the name during the temp `fsync` is `PathAccessError` (403), a hard link of the token is `EditConflictError` (409), the token intact in both.
- **In-place fallback.** The checks run on the descriptor that is written, after the open: `O_NOFOLLOW`, regular file, not a name of a private file, whole path resolved again, the name still that inode, bytes still the expected digest, in that order, and only then `ftruncate`. A swap before the open is caught by the path check after the open; a swap after the checks changes the path, not the inode the descriptor holds. Real permissions: as `nobody`, a note in a `0555` folder saved in place (`n.md` the only entry, same inode). Restore on a failed write: exact for 8 MiB, none for 8 MiB + 1 (the file is truncated; stated in the record as limit (b)). The window between `ftruncate` and the end of the write is a data-loss window for a crash; stated as limit (a).
- **Sweep.** Removes only a regular file (never a link or a folder) with the exact name, owned by the user, owner-writable, untouched for an hour; a temp file of a save under way is fresh and kept (probe: the sweep run from inside the `fsync` of a live save returned `false`); it runs on a full pass only, after the exclusion filter, on entries that are files by `readdir`. Deleting the name unlinks the name only. The exported function would remove a user file that merely matches the pattern if it is also old, regular, own and writable: by design, and the pattern boundaries are R3-3.
- **Search NUL.** `q=%00`, `q=%00%00%20%00`, `q=a%00b`, with `area`, `tag`, `ext` set to NUL, on `search`, `graph`, `recall` and `facts`: all `200` (or the declared `409`), none `500`; `recall` already caught the FTS error itself.
- **Surface.** `sdk.surface` C38 holds at `HEAD`; the mutant that adds `removeStaleSaveTemp` to the barrel makes it fail. `SAVE_TEMP_PATTERN`, `STALE_SAVE_TEMP_MS` and `removeStaleSaveTemp` are imported by path in the test, as the comment says.
- **Contract.** `PUT /api/memory/notes` declares 200, 403 `forbidden_path` and `note_not_editable`, 404, 409 `edit_conflict`, 413 (`contracts/src/api/memory.ts:462-482`); every answer I provoked is in that list. The test server validates responses by default under `NODE_ENV=test` (`apps/api/src/contract.ts:105-109`).
- **Old assertions replaced.** At `0074922` the two `toThrow(EditConflictError)` lines used an import that the internal barrel does not export, so they were `toThrow(undefined)`, which accepts any error. `toThrow(conflict())` (`tests/security-writes.test.ts:39`) needs `code: "edit_conflict"` and `statusCode: 409`; anything that passed the new form passed the old one, and the 403 mutant passes the old form (30 of 30) and fails the new one (2 tests).
