## 1. Data model: what is a node, what edges exist, and who reads each edge

### Takeaway

A node is one indexed file (a row of `files`), not a concept or entity. There are four physically stored relation tables (`file_links`, `note_links`, `file_related`, plus `file_vectors` as a similarity source) and one bi-temporal `facts` table that is not linked to files or the graph. The two link tables are inconsistent: `file_links` holds only resolved Markdown links, while `[[wikilinks]]` live only in `note_links`, and only the Links panel reads `note_links`.

### Cited Findings

- `files` row = one file: `root, path (UNIQUE, absolute), rel, name, ext, dir, area, size, mtime, indexed_at, title, tags (JSON)` — [core/src/db/migrations.ts:65-82](core/src/db/migrations.ts); `fields` (Dataview-style `key:: value`, JSON) added in migration 3 — [core/src/db/migrations.ts:162-164](core/src/db/migrations.ts).
- Full-text index: `files_fts USING fts5(name, rel, content, tokenize='porter unicode61')` — [core/src/db/migrations.ts:84-86](core/src/db/migrations.ts). The Porter stemmer is English-only; Portuguese stemming is done separately in JS only for recall/hash (`stemLite`) — [core/src/memory/recall.ts:107-131](core/src/memory/recall.ts). FTS stores only the first 200 000 characters of a file — [core/src/memory/indexer.ts:771](core/src/memory/indexer.ts).
- `file_links(src_id, dst_id, kind)` with the schema comment `markdown-link | same-dir | same-area` — [core/src/db/migrations.ts:88-93](core/src/db/migrations.ts). In practice the indexer only ever inserts `kind='markdown-link'` — [core/src/memory/indexer.ts:908-913](core/src/memory/indexer.ts), [core/src/memory/indexer.ts:848-862](core/src/memory/indexer.ts). Its own regex-based link extractor (`markdownTargets`) only matches `[text](path)` and does not skip code blocks — [core/src/memory/indexer.ts:828-845](core/src/memory/indexer.ts).
- `note_links(src_id, kind, target TEXT, label, line)` (migration 20, cerebro-v2 "door 1"): targets are stored as text and resolved at query time — [core/src/db/migrations.ts:490-505](core/src/db/migrations.ts). Kinds are `markdown-link` and `wikilink`; parser skips front matter, fenced blocks and code spans; handles `[[a|label]]`, `[[a#h]]`, `![[embed]]` — [core/src/memory/linkParser.ts:9](core/src/memory/linkParser.ts), [core/src/memory/linkParser.ts:24-50](core/src/memory/linkParser.ts), [core/src/memory/linkParser.ts:70-107](core/src/memory/linkParser.ts). Written per Markdown file at index time — [core/src/memory/indexer.ts:821-824](core/src/memory/indexer.ts), [core/src/memory/indexer.ts:865-871](core/src/memory/indexer.ts); backfilled from stored FTS text after migration — [core/src/memory/indexer.ts:878-898](core/src/memory/indexer.ts).
- `file_terms(file_id, terms JSON)` (top-80 raw term frequencies of the first 20 000 chars) and `file_related(src_id, dst_id, score, terms)` (migration 9) — [core/src/db/migrations.ts:296-321](core/src/db/migrations.ts), [core/src/memory/indexer.ts:139-144](core/src/memory/indexer.ts).
- `file_vectors(file_id PK, provider, dim, vec BLOB, mtime, size)`: at most ONE vector per file (no chunking), plain BLOB not `vec0` — [core/src/db/migrations.ts:507-523](core/src/db/migrations.ts).
- `facts(subject, predicate, object, valid_from, valid_to, source_run_id, source_path, created_at)` — [core/src/db/migrations.ts:140-161](core/src/db/migrations.ts). Subjects are free strings; no foreign key to `files` or any entity table.
- `meta(key, value)` is a generic KV used by memory for: pending unresolved links, `index.note_links` version, `related_at`, `recall.stats` (a single JSON blob of up to 500 paths), `index.semantic_error`, `last_index` — [core/src/db/migrations.ts:116-119](core/src/db/migrations.ts), [core/src/memory/indexer.ts:55-59](core/src/memory/indexer.ts), [core/src/memory/recall.ts:522-581](core/src/memory/recall.ts), [core/src/memory/vectors.ts:32](core/src/memory/vectors.ts), [core/src/memory/routers.ts:212-217](core/src/memory/routers.ts).
- Readers per edge type:
  - `file_links` (markdown-link only): graph — [core/src/memory/graph.ts:72-84](core/src/memory/graph.ts); server hygiene orphans — [core/src/memory/hygiene.ts:94-103](core/src/memory/hygiene.ts); `relatedFiles` (`GET /api/memory/related`, used by the immersive BrainScene) — [core/src/memory/graph.ts:176-198](core/src/memory/graph.ts), [apps/command-centre/src/nucleo/scenes/BrainScene.tsx:688-700](apps/command-centre/src/nucleo/scenes/BrainScene.tsx).
  - `note_links` (markdown-link + wikilink): only `linksOf` (`GET /api/memory/links`) — [core/src/memory/links.ts:106-159](core/src/memory/links.ts), [apps/api/src/routes/memory.ts:122-127](apps/api/src/routes/memory.ts) — rendered by `LinksSection` inside the 2D SecondBrain's PreviewPanel only — [apps/command-centre/src/brain/PreviewPanel.tsx:241](apps/command-centre/src/brain/PreviewPanel.tsx), [apps/command-centre/src/brain/LinksSection.tsx:19](apps/command-centre/src/brain/LinksSection.tsx).
  - `file_related`: graph `related` edges and `relatedFiles` — [core/src/memory/graph.ts:110-121](core/src/memory/graph.ts), [core/src/memory/graph.ts:199-219](core/src/memory/graph.ts).
  - `same-dir`: not stored; synthesised at graph-build time — [core/src/memory/graph.ts:86-105](core/src/memory/graph.ts). `same-area`: declared in types/schema but never emitted by `buildGraph` (only `markdown-link`, `same-dir`, `related` pushed) — [core/src/memory/graph.ts:25](core/src/memory/graph.ts), [core/src/memory/graph.ts:71-121](core/src/memory/graph.ts).
  - Recall reads none of these tables for traversal; it re-parses Markdown links from the chosen section text — [core/src/memory/recall.ts:423-440](core/src/memory/recall.ts).

### Inferences

- The "graph" is a file graph with structural (folder) and lexical-similarity edges; there are no typed semantic relations (person, project, client, decision) and no edge from facts to notes.
- Two parallel link stores (`file_links` vs `note_links`) is technical debt: cerebro-v2 added `note_links` for backlinks but did not migrate graph/hygiene/related/recall onto it.

### Gaps

- No index on `file_links(dst_id)` was found in migrations (only the PK on `src_id,dst_id,kind`), so reverse lookups scan; not measured.

## 2. Write paths: notes, journal, facts, consolidation, routines, run hooks

### Takeaway

Writes are: owner-only Markdown notes under `memory/notes/`, an append-only daily journal (auto-fed one line per finished run), API/MCP facts with exact-string contradiction handling, and an LLM-executed nightly consolidation skill that appends to `MEMORY.md`. Nothing extracts entities, deduplicates, summarises areas, or writes structured knowledge automatically from content.

### Cited Findings

Only the owner token may write notes; devices/run credentials get 403 — [.specs/STATE.md:281](.specs/STATE.md); editing only under `memory/` (not ROUTER.md, areas/, journal/) — [.specs/STATE.md:282](.specs/STATE.md).

- Routines in `routines/*.json`: `nightly-consolidation` is `"enabled": true`, cron `0 3 * * *`, profile `review_before_write` — [routines/nightly-consolidation.json](routines/nightly-consolidation.json); `daily-workspace-digest` and `service-heartbeat` are `"enabled": false` — [routines/daily-workspace-digest.json](routines/daily-workspace-digest.json), [routines/service-heartbeat.json](routines/service-heartbeat.json).

### Inferences

- The only "automatic" knowledge capture is a one-line run log in the journal; promotion to long-term memory depends on an LLM routine that, per engine semantics, waits for owner approval every night, and the docs/skill disagree about how it behaves.
- Facts dedup is exact-string: "Cliente X" vs "cliente x" or a paraphrased predicate create parallel open facts; nothing reconciles them.
- Area indexes are file listings by recency, not summaries.

### Gaps

- Whether the routine store copies `routines/*.json` into a user home or the repo root is the home itself (docs say the token lives in "the MordomoOS home (the repo root, or $MORDOMO_HOME)" — [docs/memory-guide.md:61](docs/memory-guide.md)) was not traced further.

## 3. Read paths: search, semantic, recall, routers, graph, related, hygiene, preview, links

### Takeaway

Retrieval is lexical and deterministic. UI search is strict AND of up to 8 prefix terms over FTS5 (BM25), with optional (off by default) RRF fusion with one-vector-per-file embeddings whose default provider is a 256-dim feature hash. Agent-facing `recall` is a separate per-keyword scorer with fixed hand-tuned weights, opens top-3 files, picks one section each and follows ≤2 Markdown links one hop; it uses neither vectors, wikilinks, `file_related` nor facts.

### Cited Findings

- Search query construction: split on whitespace, strip `"`, `*`, NUL, take first 8 terms, emit `"t1"* "t2"*` (implicit AND, prefix) — [core/src/memory/search.ts:30-38](core/src/memory/search.ts). No stopword removal, no OR, no stemming beyond FTS Porter. Empty query returns most recent files — [core/src/memory/search.ts:72-80](core/src/memory/search.ts).
- Semantic: off by default (`memory.embeddings.enabled: false`, provider default `hash`) — [contracts/src/settings.ts:394-430](contracts/src/settings.ts), [core/src/memory/semantic.ts:8-12](core/src/memory/semantic.ts). Fusion = RRF k=60 over BM25 list and cosine list, each depth 50 — [core/src/memory/semantic.ts:14-17](core/src/memory/semantic.ts), [core/src/memory/semantic.ts:44-51](core/src/memory/semantic.ts), [core/src/memory/semantic.ts:90-149](core/src/memory/semantic.ts). The text half is still the strict AND `searchFiles` — [core/src/memory/semantic.ts:102](core/src/memory/semantic.ts). Query-embedding failure silently falls back to text — [core/src/memory/semantic.ts:118-122](core/src/memory/semantic.ts).
- Hash provider: unigrams + bigrams (0.5 weight) of stemmed, stopword-filtered words, FNV-1a signed hashing into 256 slots, `1+ln(count)`, L2-normalised, first 20 000 chars, min similarity 0.2; explicitly "sees spelling, not meaning" — [core/src/memory/embeddings.ts:40-115](core/src/memory/embeddings.ts). HTTP provider: OpenAI-style `POST {model,input}`, batches of 16, 8 000 chars per text, 30 s timeout, 8 MB cap, loopback or https+`sendRemote` only, key from env var named by `apiKeyEnv` — [core/src/memory/embeddings.ts:117-249](core/src/memory/embeddings.ts), [core/src/memory/embeddings.ts:259-267](core/src/memory/embeddings.ts).
- Vectors: only `.md/.markdown/.txt` embedded; text is the first `maxChars` of the FTS content (one vector per whole file); turning embeddings off deletes all vectors next pass; ranking by `vec_distance_cosine` (sqlite-vec) or JS cosine fallback — [core/src/memory/vectors.ts:30-33](core/src/memory/vectors.ts), [core/src/memory/vectors.ts:85-118](core/src/memory/vectors.ts), [core/src/memory/vectors.ts:211-247](core/src/memory/vectors.ts).
- Measured value of hash vectors (project's own test): hybrid finds 11/12 on fixed corpus, strict AND finds 5, but a plain OR of words also finds 11 — "the gain … comes from not requiring every word" — [tests/memory.semantic.test.ts:86-104](tests/memory.semantic.test.ts), [tests/memory.semantic.test.ts:245-275](tests/memory.semantic.test.ts); same statement in [docs/memory-guide.md:280-291](docs/memory-guide.md) and owner question 16 — [.specs/STATE.md:284](.specs/STATE.md), [.specs/STATE.md:298](.specs/STATE.md).
- Recall layers: (1) keywords — fold accents, en/pt stopwords, `stemLite`, path-like tokens kept, max 8 — [core/src/memory/recall.ts:83-164](core/src/memory/recall.ts); (2) candidates — one FTS query per keyword (`"kw"*`), `bm25(files_fts, 8.0, 3.0, 1.0)` capped at 10 per keyword, then +6 name, +4 title, +3 tags, +1.5 path per keyword, +5 per matched keyword, +8 if a router points at the file, +4 if a keyword names the file's area; candidate limit 60 per keyword — [core/src/memory/recall.ts:224-308](core/src/memory/recall.ts); (3) open top K=3 (max 10), split by headings (non-MD: 40-line chunks), section score heading +3, body `1+log2(1+n)`, +2 per distinct keyword, ×0.85 over 4 000 chars — [core/src/memory/recall.ts:319-379](core/src/memory/recall.ts), [core/src/memory/recall.ts:444-448](core/src/memory/recall.ts); (4) follow ≤2 Markdown `[x](path)` links from the winning section, one level, keep if higher — [core/src/memory/recall.ts:423-440](core/src/memory/recall.ts), [core/src/memory/recall.ts:485-504](core/src/memory/recall.ts). Excerpt cap 1500 chars; tokens estimated as chars/4 — [core/src/memory/recall.ts:447](core/src/memory/recall.ts), [core/src/memory/recall.ts:507](core/src/memory/recall.ts). Generated routers are excluded as candidates — [core/src/memory/recall.ts:247](core/src/memory/recall.ts). Run credentials recall only from `memory/` — [apps/api/src/routes/memory.ts:207-217](apps/api/src/routes/memory.ts).
- Router pointers parsed from ROUTER.md/areas/*.md: backtick absolute paths and Markdown links — [core/src/memory/recall.ts:172-204](core/src/memory/recall.ts).
- Graph: default 400 nodes, hard cap 4000; filter `area`, `dir LIKE`, `query` as `name LIKE %q% OR rel LIKE %q%`; nodes `ORDER BY mtime DESC LIMIT maxNodes` — [core/src/memory/graph.ts:42-69](core/src/memory/graph.ts). Reads the ENTIRE `file_links` table every request and filters in JS — [core/src/memory/graph.ts:72-84](core/src/memory/graph.ts). Same-dir edges: a star from the first (most recent) file of each dir to at most the next 39 files (`i < 40`) — [core/src/memory/graph.ts:94-105](core/src/memory/graph.ts). Related edges only among included nodes — [core/src/memory/graph.ts:149-174](core/src/memory/graph.ts). Graph route passes no read-time policy filter (`allow`), unlike search and links — [apps/api/src/routes/memory.ts:102-127](apps/api/src/routes/memory.ts).
- Related edges: TF-IDF over stored top-80 TF terms (first 20 000 chars), terms in ≥60% of docs dropped, cosine, keep pair if in either side's top-3 and ≥0.18; recomputed incrementally for changed files — [core/src/memory/related.ts:94-188](core/src/memory/related.ts), [core/src/memory/indexer.ts:955-993](core/src/memory/indexer.ts). Stopword list en+pt — [core/src/memory/related.ts:36-48](core/src/memory/related.ts).
- Hygiene (server): orphans = `.md` with no `markdown-link` row in `file_links` (routers excluded); dangling router pointers; stale = any file `mtime` older than 90 days; skills never run; silent routines; unused connectors — [core/src/memory/hygiene.ts:69-184](core/src/memory/hygiene.ts). The UI never calls `/api/memory/hygiene` (no `memory/hygiene` call site in `apps/command-centre/src`; grep); the UI computes its own hygiene client-side, where an orphan is a file with no edge of ANY kind in the loaded graph (incl. same-dir/related) — [apps/command-centre/src/brain/engine/graph.ts:106-126](apps/command-centre/src/brain/engine/graph.ts), [docs/memory-guide.md:235-240](docs/memory-guide.md).
- Router check: missing area indexes, broken backtick pointers, router older than last index by >1 day — [core/src/memory/routers.ts:156-202](core/src/memory/routers.ts).
- Preview: safe read-only text preview, known-binary extensions refused, NUL-sniff, capped at `previewMaxBytes` (256 KiB default) — [core/src/memory/preview.ts:101-135](core/src/memory/preview.ts), [contracts/src/settings.ts:336-340](contracts/src/settings.ts). No PDF/DOCX text extraction (those extensions are classed binary) — [core/src/memory/preview.ts:14-21](core/src/memory/preview.ts).
- Links: backlinks = `note_links` markdown targets equal to the path + wikilinks whose key resolves to this file; wikilink resolution prefers same folder, then shortest rel path, then alphabetical; alternatives listed — [core/src/memory/links.ts:58-91](core/src/memory/links.ts), [core/src/memory/links.ts:106-159](core/src/memory/links.ts).

### Inferences

- Three different lexical matchers coexist (strict-AND FTS for search, per-keyword OR-ish scoring for recall, substring `LIKE` for graph `q`, plus client-side substring filtering), so the same question gives different results in each surface.
- Recall's weights are hand-set constants with no learning, no reranker, no use of embeddings even when enabled, and no hybrid with `file_related`.

### Gaps

- No latency/quality benchmarks for recall beyond `tests/api.recall-quality.test.ts` fixtures were read in detail.

## 4. Confirmation of suspected issues (a)–(f)

### Takeaway

(a), (b), (c), (d), (e) are confirmed by code; (f) is confirmed as "missing" with grep evidence. Additional issues found: graph/related bypass the read-time policy filter, `same-area` edges are never produced, same-dir edges cap at 40 per folder, recall ignores wikilinks/vectors, and docs contradict the routine file.

### Cited Findings

- (a) CONFIRMED. Graph draws only `file_links` markdown-link rows — [core/src/memory/graph.ts:72-84](core/src/memory/graph.ts); `file_links` never receives wikilinks (insert is hard-coded `'markdown-link'` from `markdownTargets`, a `[..](..)` regex) — [core/src/memory/indexer.ts:828-862](core/src/memory/indexer.ts), [core/src/memory/indexer.ts:908-913](core/src/memory/indexer.ts); server hygiene orphan query uses the same table — [core/src/memory/hygiene.ts:94-103](core/src/memory/hygiene.ts). So a note linked only via `[[wikilink]]` (in or out) has no link edge in the graph and is reported as an orphan by `/api/memory/hygiene`. Also `relatedFiles` (immersive scene's "related" rail) uses `file_links` — [core/src/memory/graph.ts:176-198](core/src/memory/graph.ts). Nuance: the client-side orphan check counts same-dir/related edges too, so in the UI such a note is only an "orphan" if it is also alone in its folder and has no similar file — [apps/command-centre/src/brain/engine/graph.ts:106-126](apps/command-centre/src/brain/engine/graph.ts). Additional nuance: `markdownTargets` does not skip code blocks, while `extractLinks` does, so the two tables can disagree even for Markdown links — [core/src/memory/indexer.ts:828-845](core/src/memory/indexer.ts) vs [core/src/memory/linkParser.ts:24-50](core/src/memory/linkParser.ts).
- (b) CONFIRMED. UI search calls `GET /api/memory/search` (`limit: 8`) — [apps/command-centre/src/views/SecondBrain.tsx:315-333](apps/command-centre/src/views/SecondBrain.tsx), [apps/command-centre/src/nucleo/scenes/BrainScene.tsx:771-792](apps/command-centre/src/nucleo/scenes/BrainScene.tsx), [apps/command-centre/src/components/CommandPalette.tsx:362-375](apps/command-centre/src/components/CommandPalette.tsx) — which builds `"t1"* "t2"* …` (AND of every token incl. stopwords like "what", "the", "o", "de") — [core/src/memory/search.ts:30-38](core/src/memory/search.ts). The cerebro-v2 plan itself records: "uma pergunta com um termo que o documento não tem devolve zero linhas" — [.specs/features/cerebro-v2/plan.md:14-15](.specs/features/cerebro-v2/plan.md). Recall instead strips stopwords and runs one FTS query per keyword, accumulating coverage — [core/src/memory/recall.ts:234-257](core/src/memory/recall.ts). ## 6. How skills and agents get memory context

### Takeaway

Agents get memory via (1) the compiled AGENTS.md/CLAUDE.md, which embeds ROUTER.md (area table, recall hint, 2 days of journal) and generic ground rules; (2) a locations block for skills listed in `settings.memorySkills` (default `recall`, `consolidate-memory`) giving paths and a run-scoped API token; (3) the MCP server with `recall`, journal, facts and note tools. There is no automatic per-run memory injection (no pre-run recall, no profile of the business/owner).

### Cited Findings

- `locationsBlock`: every skill gets its folder; memory skills additionally get home, memory folder, `MEMORY.md` path, journal path pattern, and `MORDOMO_URL`/`MORDOMO_RUN_TOKEN` instructions — [core/src/skills/catalog.ts:404-422](core/src/skills/catalog.ts). `buildRunPrompt` adds skill file path, locations, inputs, artifacts dir, read-only notice, and up to the last 4000 chars of the skill's own NOTES.md — no recall results or MEMORY.md content are injected — [core/src/skills/catalog.ts:424-450](core/src/skills/catalog.ts).
- `memorySkills` default `["recall", "consolidate-memory"]` — [contracts/src/settings.ts:363](contracts/src/settings.ts); wired to catalog — [core/src/engine.ts:262](core/src/engine.ts).
- Recall skill: instructs agent to run `mordomo recall "<q>" --json` (or the API), read only `answerContext`, rephrase once, cite `path § section`, and log durable facts in the journal — [skills/recall/SKILL.md:47-75](skills/recall/SKILL.md).
- Compiled instructions file: `routerBody()` = ROUTER.md minus header comment, or a placeholder "No memory routers generated yet" — [core/src/sync/compiler.ts:301-313](core/src/sync/compiler.ts); `agentsFileContent` sections: header, "Memory router", "Available skills", "Ground rules" (4 bullets) — [core/src/sync/compiler.ts:315-342](core/src/sync/compiler.ts); one file per distinct instructions filename among enabled providers — [core/src/sync/compiler.ts:106-118](core/src/sync/compiler.ts).
